# Album Dock — 개발 프리뷰 0.1.4

만든 사람: **찌모킹**

YT Music을 둘러보고 앨범을 담아, MP3와 커버를 가수/앨범 폴더로 정리하는 Intel Mac용 데스크톱 앱입니다. iPod classic 2007을 위한 출력 설정을 기본으로 사용합니다.

## 0.1.4 수정

- 내 음악의 기본 보기를 커버플로우로 바꿨습니다. 격자 보기로 전환할 수 있으며 보기 방식은 기억합니다.
- 앨범 클릭, 마우스 휠·트랙패드, 좌우 버튼, 슬라이더로 이동합니다. 커버 영역에 초점을 맞추면 방향키·Home·End로 이동하고 Enter로 폴더를 엽니다.
- 선택한 표지를 더블클릭하거나 ‘앨범 폴더 열기’를 누르면 Finder에서 엽니다.
- 검색, 커버 없는 앨범, 애니메이션 줄이기 설정을 지원합니다.
- 타입 검사와 빌드는 통과했습니다. 이 환경에서는 브라우저 실행이 제한되어 화면·상호작용의 실제 검증은 아직 남아 있습니다.

## 0.1.3 수정

- 설정의 ‘YouTube 로그인을 다운로드에도 사용’을 켜면 다음 작업부터 앱 내 YouTube 세션을 사용합니다. 기본값은 꺼짐입니다.
- 앱에서 해당 곡이 재생되는 계정으로 로그인한 뒤 설정을 켜고, 다운로드함에서 실패한 앨범을 다시 시도하세요. 완료된 곡은 건너뜁니다.
- YouTube 도메인의 쿠키만 작업 프로세스의 표준입력으로 전달하며, 메모리 쿠키 저장소를 사용합니다. 쿠키 파일·명령행 인자·작업 기록에는 저장하지 않습니다. 외부 Chrome의 쿠키는 읽지 않습니다.
- 로그인 사용 중 발생한 다운로드 오류는 인증 정보 노출을 막기 위해 안내 문구로 표시합니다. 로그인을 사용하더라도 계정의 연령 확인과 서비스 제한에 따라 실패할 수 있습니다.
- 제작자 ‘찌모킹’을 설정 화면과 패키지 정보에 표시합니다.
- 실제 사용자 계정으로 연령 제한 곡 다운로드 성공 여부는 아직 검증하지 않았습니다.

## 0.1.2 수정

- 배포용 Python의 HTTPS 연결에 필요한 인증서 정책 파일을 번들에 포함하여 앨범 담기의 `Connection aborted / FileNotFoundError`를 수정했습니다.
- 패키징 전에 실제 작업 실행파일의 TLS 초기화를 검사합니다. 인증서 검증은 유지합니다.

## 0.1.1 수정

- `www.youtube.com/musicpremium`으로 이동할 때 앱의 주소 허용 목록에 걸리던 문제를 수정했습니다.
- YouTube와 Google의 로그인 세션 전달 주소를 명시적으로 허용했습니다.
- 정상적인 페이지 전환 중 발생하는 `ERR_ABORTED (-3)`를 연결 오류로 표시하지 않습니다. DNS·인증서 등 실제 오류는 계속 표시합니다.
- 차단된 외부 주소는 인증 쿼리 문자열을 제외한 도메인만 안내합니다.
- 관련 회귀 테스트 7개와 TypeScript 검사를 통과했습니다. 실제 Google 계정 로그인 성공 여부는 아직 확인하지 못했습니다.

## 실행

`release/Album Dock-darwin-x64/Album Dock.app`을 Finder에서 열어 주세요. Python, Node.js, FFmpeg를 따로 설치할 필요가 없습니다. Intel Mac / macOS 13 이상용이며, 개발용 로컬 서명을 적용했습니다. Apple 공증을 받은 배포판은 아닙니다. `src/index.html`을 브라우저에서 여는 방식으로는 앱이 실행되지 않습니다.

1. **YT Music**에서 앨범을 검색해 앨범 상세 페이지를 엽니다.
2. 상단 **이 앨범 담기**를 누릅니다.
3. 커버, 앨범명, 앨범 아티스트, 발매 연도와 수록곡을 확인합니다.
4. **앨범 저장**을 누르면 다운로드함에서 진행됩니다.
5. **내 음악**에서 저장한 앨범과 기존 컬렉션을 봅니다. 앨범을 누르면 Finder에서 해당 폴더가 열립니다.

기본 저장 위치는 바탕화면의 `음악`입니다. **설정**에서 폴더와 MP3 비트레이트를 바꿀 수 있습니다. 이미 대기열에 들어간 앨범에는 담을 때의 설정이 유지됩니다.

## 이번 버전에 구현한 기능

- 격리된 Chromium 내장 브라우저, 검색, 뒤로/앞으로, 새로고침
- 현재 보고 있는 앨범 주소 감지 및 앨범 미리보기
- 앨범 단위 대기열, 진행 상태, 취소, 실패한 곡 재시도
- SQLite 작업 기록 및 중단된 작업 복구
- MP3 192/256/320 kbps, 44.1 kHz, 스테레오
- ID3v2.3 한글 태그, 앨범 아티스트, 트랙 번호, JPEG 커버 삽입
- 커버는 원본 비율을 유지하며 최대 600×600, 별도 `cover.jpg` 저장
- 기존 가수/앨범 폴더 읽기, 커버 목록과 검색
- 기존 파일 덮어쓰기 방지, 앱이 완료한 곡 재다운로드 방지

## 저장과 복구

완성된 파일은 `가수/앨범/01 곡 제목.mp3` 구조로 저장합니다. 앨범마다 `.albumdock.json`에 완료한 곡을 기록합니다. 같은 이름의 기존 앨범이 앱에서 관리하던 앨범인지 확인할 수 없으면 이름 뒤에 구분자를 붙여 별도 폴더에 저장합니다. 기존 음악을 임의로 이동하거나 수정하지 않습니다.

변환 전 파일은 저장 폴더 아래 `.albumdock-work`에서 처리하고, 검증이 끝난 MP3를 최종 위치에 등록합니다. 정상 종료된 작업의 임시 파일은 정리됩니다. 강제 종료 시 임시 파일이 남을 수 있습니다. 재시도는 완료된 MP3를 확인한 뒤 빠진 곡부터 진행합니다.

## 확인된 내용과 아직 확인하지 못한 내용

확인 완료:

- TypeScript 검사 및 프로덕션 번들 생성
- MP3 생성·한글 ID3v2.3·커버·파일 보존·재시도·경로 검사 등 8개 자동 테스트
- 실제 `Overgrown / James Blake` 앨범의 수록곡 10개와 공개 재생목록 ID 연결
- 공개 시험 영상의 오디오 다운로드
- 기존 음악 폴더 45개 앨범 / 453곡을 읽기 전용으로 인식
- 실제 컬렉션 데이터를 사용한 브라우저 기반 UI 미리보기 검증
- 음악 처리 실행 파일의 독립 실행 및 FFmpeg 동작

미확인 / 첫 실행에서 확인할 부분:

- 이 개발 환경에서는 macOS LaunchServices 연결이 차단되어 Electron 앱 창을 실행하지 못했습니다. 최종 `.app`의 전체 실행 흐름과 Electron IPC는 Finder에서 실행해 확인해야 합니다. 화면 미리보기는 실제 앱 실행 검증을 대신하지 않습니다.
- 내장 브라우저에서의 Google 로그인과 YT Music 재생은 아직 확인하지 못했습니다. Google 정책에 따라 로그인이 제한될 수 있습니다. 브라우저 쿠키를 외부에서 가져오거나 차단을 우회하는 기능은 없습니다.
- 서비스 제한, 비공개/유료 콘텐츠, 연령 제한 등에 따라 가져올 수 없는 곡은 실패로 표시합니다.
- 실제 아이팟의 Cover Flow, 한글 표시 및 동기화 결과는 케이블 연결 후 확인해야 합니다.

현재 보관함은 조회와 폴더 열기를 지원합니다. 기존 파일의 태그 일괄 수정, 다중 디스크 수동 편집, 직접 아이팟 동기화, 자동 업데이트는 후속 개발 범위입니다. 지금은 기존 동기화 프로그램으로 완성된 MP3를 아이팟에 넣습니다.

## 개발 구조

- `electron/main.ts`: 창, 격리된 YT Music 화면, IPC 검증, 작업 대기열, SQLite
- `electron/preload.ts`: 화면에 노출하는 최소 API
- `src/app.tsx`: React 화면
- `worker/album_worker.py`: 앨범 메타데이터, yt-dlp, FFmpeg, Mutagen, 보관함 조회
- `tests/test_worker.py`: 임시 폴더에서 실제 MP3를 만드는 자동 검증
- `tests/smoke.cjs`: 네이티브 창을 실행할 수 있는 환경에서 실행하는 통합 검증

## 다시 빌드하기

Node.js 22.12 이상, Python 3.12 기준입니다. 의존성 버전은 `package-lock.json`과 `worker/requirements.txt`에 기록했습니다.

```sh
npm ci
node node_modules/electron/install.js
python3 -m venv .venv
.venv/bin/python -m pip install -r worker/requirements.txt
npm run typecheck
npm run test:navigation
npm run build
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/pyinstaller --noconfirm --distpath resources \
  --workpath .build/worker worker/album-worker.spec
npm run package
```

개발 중에는 위와 같이 작업 실행 파일을 빌드하거나, `ALBUM_DOCK_PYTHON`에 개발용 Python 실행 파일의 절대 경로를 지정할 수 있습니다.

개발 실행은 `npm start`입니다. `ALBUM_DOCK_DATA`를 지정하면 테스트용 SQLite와 브라우저 프로필을 별도 폴더로 분리할 수 있습니다. `ALBUM_DOCK_OUTPUT`은 최초 실행의 기본 저장 폴더를 바꿉니다.

상용 배포 전에는 앱 서명·공증, 번들 의존성 라이선스 고지 및 배포 요건을 별도로 점검해야 합니다.
